## 1. Executive Summary

As cloud adoption in Europe matures under strict regulatory frameworks (such as GDPR, NIS2, and DORA), hyperscale cloud service providers—Amazon Web Services (AWS), Microsoft Azure, and Google Cloud Platform (GCP)—have introduced localized data residency boundaries and sovereign cloud options. A key area of compliance involves **support data, diagnostic logs, and system-generated telemetry**.

- **AWS**: Guarantees customer data residency within selected EU regions for standard services. Support interaction logs and ticket attachments in standard regions may be processed globally unless using **AWS European Sovereign Cloud**, which mandates EU-only operations and EU-resident personnel for technical support and maintenance.
- **Azure**: Through the **Microsoft EU Data Boundary (EUDB)**, Azure guarantees that customer data, system-generated logs (e.g., diagnostic and activity logs), and technical support data reside strictly within the EU/EFTA boundary, with support operations routed to EU-located personnel.
- **GCP**: Offers **Regional Log Buckets** in Cloud Logging to enforce that log entries reside in specified EU regions. Under **Assured Workloads for EU** (EU Data Boundary & Support control package), GCP guarantees support data residency, restricts support access to EU personnel, and provides Access Transparency/Approval mechanisms.

## 2. Deep-Dive Analysis by Cloud Provider

### 2.1 Amazon Web Services (AWS)

* **Customer Data vs. Log Data**: Standard AWS EU regions (e.g., `eu-central-1` Frankfurt, `eu-west-1` Ireland) guarantee that Customer Data (stored in S3, EBS, RDS, etc.) does not leave the region unless initiated by the customer.
* **CloudTrail & Logging**: CloudTrail logs and CloudWatch logs are stored in the customer's chosen region by default.
* **Support Ticket & Diagnostic Logs**: In standard AWS support plans, diagnostic logs uploaded to support cases or support ticket content may be accessed by global AWS support engineers unless restricted by specific enterprise support tier agreements or dedicated sovereign configurations.
* **AWS European Sovereign Cloud**: An independent, EU-operated cloud environment. Under this model, zero operational control data or logs cross EU borders, and day-to-day operations, maintenance, and technical support are performed exclusively by EU-resident AWS employees.

### 2.2 Microsoft Azure

* **EU Data Boundary (EUDB)**: Microsoft's comprehensive commitment for EU/EFTA enterprise customers covering Azure, M365, and Dynamics 365.
* **Logging Scope & System-Generated Logs**: System-generated logs (Azure Activity logs, diagnostic logs, metric streams, Azure Monitor logs) generated by resources deployed in EU regions are processed and stored within the EU Data Boundary. Personal data embedded in system telemetry is pseudonymized.
* **Support Data Residency**: Customer diagnostic data submitted during support tickets and support interactions are stored within the EU Data Boundary. Microsoft routes support requests to EU-located support teams under EUDB guidelines.
* **Exceptions & Transparency**: Microsoft publishes a documented list of limited continuing cross-border transfers required for global security operational threat telemetry, which are pseudonymized and minimized.

### 2.3 Google Cloud Platform (GCP)

* **Cloud Logging Regional Storage**: GCP Cloud Logging allows users to define custom log buckets locked to specific regional locations (e.g., `europe-west1` Belgium, `europe-west3` Frankfurt). Log entries written to regional buckets do not leave the target region at rest.
* **Assured Workloads (EU Data Boundary & Support)**: Provides compliance boundary enforcement. Ensures customer logs, diagnostic artifacts, and support case data remain within EU boundaries.
* **Personnel & Access Transparency**: Under EU Assured Workloads, technical support is handled by EU-resident personnel. GCP provides **Access Transparency** logs (real-time logs when Google support/engineering accesses customer logs or data) and **Access Approval** (requires explicit customer approval before Google engineers can view logs).
